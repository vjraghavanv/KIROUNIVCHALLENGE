# Requirements — Document Checklist

## Introduction

The Document Checklist lets a citizen see exactly which documents a service
requires, tick off the ones they already have, and receive a computed
application-readiness status: READY, NOT READY, or NEEDS VERIFICATION. The
readiness status is derived deterministically from the service's official
document requirements — never generated by the model.

This feature obeys `data-governance.md` (document kinds: required / conditional /
optional) and the `ai-rag.md` rule that readiness is computed, not hallucinated.

## Dependencies

- **official-knowledge-base** — supplies the authoritative `DocumentRequirement`
  list per service.
- **government-service-discovery** — provides the resolved service whose
  documents are checked.
- **multilingual-assistant** — renders document names and conditions in the
  citizen's language.

## Requirements

### Requirement 1 — Present the official document set

**User story:** As a citizen, I want to see the documents a service needs, so
that I know what to gather.

#### Acceptance criteria

1. WHEN a service is resolved THEN the system SHALL list its documents grouped by
   kind: required, conditional, optional.
2. WHEN a conditional document is shown THEN the system SHALL display its
   condition.
3. IF the service record lists no documents THEN the system SHALL display
   "Official information not available in the current knowledge base." rather
   than an empty implication of "no documents needed."

### Requirement 2 — Let citizens mark documents they have

**User story:** As a citizen, I want to tick documents I already possess, so that
I can see what remains.

#### Acceptance criteria

1. WHEN a citizen marks a document as available THEN the system SHALL record that
   selection for the current session.
2. WHEN a citizen unmarks a document THEN the system SHALL update readiness
   accordingly.
3. WHILE the citizen edits selections THE system SHALL not persist any
   government-issued identifier value (only the fact that a document type is
   held).

### Requirement 3 — Compute application readiness deterministically

**User story:** As a citizen, I want a clear readiness status, so that I know
whether I can proceed.

#### Acceptance criteria

1. WHEN all required documents are marked available AND all applicable
   conditional documents are satisfied THEN the system SHALL report READY.
2. IF any required document is not marked available THEN the system SHALL report
   NOT READY and SHALL NOT report READY.
3. IF the service `status` is `unverified` OR a required document lacks a backing
   source THEN the system SHALL report NEEDS VERIFICATION.
4. WHEN readiness is computed THEN it SHALL be derived only from the record's
   documents and the citizen's selections, never from model output.

### Requirement 4 — Conditional document logic

**User story:** As a citizen, I want conditional documents to matter only when
they apply, so that I am not blocked by irrelevant items.

#### Acceptance criteria

1. WHEN a conditional document's condition does not apply to the citizen THEN it
   SHALL NOT affect readiness.
2. WHEN a conditional document's condition applies THEN it SHALL be treated as
   required for readiness purposes.
3. WHERE the system cannot determine whether a condition applies THEN it SHALL
   report NEEDS VERIFICATION rather than guessing.

### Requirement 5 — Show missing and remaining items

**User story:** As a citizen, I want to see what I am missing, so that I can act.

#### Acceptance criteria

1. WHEN readiness is NOT READY THEN the system SHALL list the specific missing
   required (and applicable conditional) documents.
2. WHEN a document is optional THEN the system SHALL clearly distinguish it from
   mandatory items.

### Requirement 6 — Source and trust

**User story:** As a citizen, I want to know where the document requirements come
from, so that I can verify them.

#### Acceptance criteria

1. WHEN the checklist is displayed THEN the system SHALL show the official
   source(s) for the document requirements.
2. WHEN a required document lacks a source reference THEN the system SHALL flag
   it for verification rather than presenting it as confirmed.
